# orchestrated-build

把超出单次上下文的构建或重写**委托给多个子代理，并由自己独立验收**的 agent skill。

## 它解决什么

把大工程交给别的 agent 时，最常见的失败不是"工人做得差"，而是：

- **没人写方案** —— 用户中途打断纠正，已完成的工作作废；
- **规格不完整** —— 工人按最小做法猜，猜错了一条没人写下来的规则；
- **采信自述** —— 交付物其实不成立，而你以为它成立。

这个 skill 把「冻结方案 → 产出契约 → 按切片派活 → 自己复现证据 → 留可审计文档」固化成可重复的流程，并明确**每一步的工件**。

## 什么时候用

准入判据（用 / 不用 / 档位怎么定）见 **`SKILL.md`「何时使用」与「档位」**——唯一定义在那里，本文件不复制。

## 安装

把本目录放到你的 agent 技能目录，例如：

```
~/.agents/skills/orchestrated-build/
```

> 新建 skill 后需要**开新会话**才能通过 `skill://` 被引用（技能列表是会话启动时的快照）；在此之前让工人直接读文件路径。

## 文件

文件清单与各文件的职责见 **`SKILL.md` 的「文件」表**（唯一定义；本文件不复制——两处清单必然漂移）。

## 作用域（如实声明）

它来自**一次**真实运行（Go→Rust 重写：18 窗口 / 20 轮 / 0 次退回 / 431 测试；7 个真实缺陷被拦下）+ **四轮**对照测试 + **九轮**审查。

**这不是"照做就能成功"的证据**：样本量小、受试者是同一模型、**触发精度未验证**，且其中一次试跑自身就没达到本文档要求的完整性。详见 `VALIDATION.md` 开头的「证明什么、不证明什么」。
