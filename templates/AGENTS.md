# 工人合同模板（随派工指令下发）

> 用法：`<>` 处按项目替换。
> 读取与写入边界仅约束本轮实现工人。仓库级工程约定沿用现有 `AGENTS.md` / `CLAUDE.md`；新增通用约定时合并到原文件，不覆盖原有要求。不要把工人专属边界写成全员约束。
> **本文件分两部分**：
> - **【通用】** —— 保留适用的行为约束，填写或替换维护者提示后下发。
> - **【示例】** —— **按项目取舍，不要照抄**。它们是"常见形态"，不是默认约束；每个项目该有自己的答案。
>
> 判断某个约束该不该写：**它是"任何项目都成立"，还是"我这个项目的选择"？** 后者要么删，要么标成项目决定并给出理由。

### 材料读取边界

**在现有项目内重构与增量开发**：读取本轮指令列出的相关实现、调用方和测试，范围不足时报告具体缺口。**替换旧项目的重写与从零构建**：默认不读旧项目或参考实现；只有主代理在本轮指令中预先列出的材料可读。报告缺失的行为判据，不以申请读取旧实现代替契约缺口报告，不自行越界。

读取到的旧实现用于取证，不自动成为需求。

**记录目录 `orch-doc/` 的例外只有一处**：`orch-doc/handoffs/`（跨轮交接文档）。
`orch-doc/` 下的**其余内容一律禁止读**——总纲 / 决策记录 / 缺口表 / 台账 / 流水 / 验收都是**架构者视角**（未定的决策、对你表现的记录、架构者自己的失误）。读它会污染你的判断。**规格必须由本轮指令与仓库内契约提供，不得从记录目录里"找背景"。**
> 这一条**是约定，不是技术隔离**：`orch-doc/` 就在你的工作目录里，工具层面拦不住你。越界读会在验收时被核对。

## 4. 编码约定

### 4.1 错误处理 【示例 + 一条通用】

**通用**：对外错误消息只包含适合公开的上下文；可能携带凭据或内部敏感信息的原始错误，先筛选并脱敏。

**按项目定**：错误类型怎么组织（每包一个 / 全局一个）、失败怎么分类、哪些错误可重试。
> ⚠ 若项目有"重试/永久失败/阻断"这类**失败分类**，它必须与 `docs/` 里的规格一致——分类错误的后果是丢数据或无限重试。

### 4.2 并发与阻塞 【示例】

**按项目定**：并发模型、阻塞调用怎么隔离、取消语义。**只在项目真有并发时才写。**

### 4.3 日志 【示例 + 一条通用】

**通用**：敏感值在进入输出前脱敏；脱敏路径遵循项目既有约定。

**按项目定**：结构化还是文本、字段约定、级别划分、输出格式由谁决定。

### 4.4 文件与命名 【示例】

**只在项目真的写文件时才写。** 常见形态：长度预算、跨平台清洗、写入顺序（临时文件 → fsync → rename）、同名冲突后缀。
> ⚠ 如果项目对**数据正确性**有要求（不丢、不重、不坏），这些约束就不是风格问题，而是必须写清并配测试的**不变量**。

### 4.5 测试 【通用】

- 测试文件的位置遵循**本语言 / 本仓库的惯例**——**不要照搬别的语言**（Rust 在被测模块同文件里放 `mod tests`；Go 用同包的 `_test.go`；Python 用独立的 `test_*.py`）。跨模块集成测试放独立目录。
- 单元测试使用合成数据、临时目录及隔离数据库。真实服务集成核验按本轮明确的授权、目标与数据边界执行。
- 测试夹具禁止**真实标识符**（真实 id、真实数据文件名、真实路径）。**域名例外**：当被测行为本身与域名相关时，允许真实域名，但路径与 id 必须合成。
- 涉及超时/取消的测试必须**同步在可观测事件上**，不得依赖毫秒级 sleep。
- 断言契约要求的行为、边界、不变量与状态迁移。内部算法状态、结构或配置若本身就是契约要求，可以验证；不把 mock 回声或源码字符串匹配当作行为证明。
- 按本轮指令列出的验证方法与证据要求核对不变量（主代理从 `references/verification.md`「验收强度要匹配风险」提取适用内容，下发时替换此提示，不要求工人读取 skill 文件）。采用测试时，测试名或说明能对应不变量编号。
