# 冻结方案（闸门 A 的工件）

> 用法：填完这份文件，**交给用户**。形态取决于是否已有授权（见下与 `SKILL.md`「闸门」）：
> **已明确要求做**（"帮我做 X"）⇒ **通报**，然后继续推进，方案可随时叫停；**只给方向 / 含不可逆操作 / 代价超预期** ⇒ **停下等批准**。**沉默不是同意。**
> **落盘位置**：被构建仓库里的 `docs/freeze-plan.md`——**只放这一个地方**。
> 理由：工人只读「仓库内文件 + 交接目录」（见 `templates/AGENTS.md §1`），放到记录目录里工人就读不到边界。
> 若你确实只能放在记录目录，**必须**把目标 / 非目标 / 硬约束逐条抄进本轮指令。
> 判据：用户读完这份文件能回答"要不要做、做成什么样、我什么时候能看见东西"。

## 0. 档位（**必须和用户一起定，不得自设**）

> **档位的唯一定义在本表。** 别处只引用，不重复份数——重复的清单必然漂移（本 skill 自己踩过：同一份数曾同时写成 3 份和 4 份）。
> 这里只做勾选与留痕。

| | lite | heavy |
|---|---|---|
| **适用** | 交付物 ≤5 个文件、单模块、无不可逆操作、不跨会话 | 跨模块 / 跨语言、含不可逆操作、长期维护、多人可见 |
| **文档** | 总纲 + 缺口 + 验收 + 台账 + 交接 | 再加：决策记录 / 切片计划 / 窗口协议 / 流水 / 完成总结（各份角色见 `references/gates.md`） |
| **验收** | 门禁 + 抽查 + **高风险**核心不变量各一个反例 | 同上 + 每片一份验收记录 + 逐条核对"无法验证清单" |
