# 派活：先分清委托的目的

**委托有两种目的，判据完全不同。先问自己"我要的是产出物，还是结论"。**

| 目的 | 你要的东西 | 详见 |
|---|---|---|
| **生产型** —— 让别处把活干出来 | 交付物（代码、文档、修复） | 本文「生产型」节 |
| **隔离型** —— 让别处烧掉上下文，只带回结论 | 压缩后的结论 + 出处 / 实验 / 真实响应 | 本文「隔离型」节 |

> 并行修多个独立 bug（按问题域分片、互不干扰）是生产型的特例，见 **`dispatching-parallel-agents`** 技能；本文不重复。

---

# 生产型：新进程 vs 子代理

| 维度 | 新进程（独立 agent 会话） | 子代理（同一 harness 内） |
|---|---|---|
| 上下文 | **独立，不挤占我的预算** | 与我共享进程预算 |
| 续接 | **能**（同一会话继续） | 不能，结束即终结 |
| 中途纠正 | **不能**（无法中途说"停，你理解错了"） | **能**（发消息 steering） |
| 双向提问 | 不能 | 能 |
| 结构化产出 | 要自己解析文本 | 可强制 schema |
| 审计 | **每窗口一份完整 transcript** | 有历史，但不如独立文件干净 |
| 进程管理 | **要我自建**：启动 / 超时 / 静默死亡 / 退出码 / 续轮 | harness 全包 |
| 可见性 | 差（只有"文件在长"和"文件系统在变"两个信号） | 好 |
| 崩溃隔离 | **强** | 同进程 |
| 并行 | 受机器与配额限制 | 有上限，且与我的轮次耦合 |

# 隔离型：让别处烧上下文，只带回结论

**要派就派，别自己先跑一遍**；子代理回我 5000 字散文等于没隔离 ⇒ 指令必须**约束输出形状**（结构化、结论在前、有长度上限、每条带可定位出处）。

## 该不该隔离，只问一句

> **这份探索能不能被我自己的便宜手段压掉？**

- **能**（grep / 去重 / 抽样 / **写个脚本批量提取**）⇒ **自己做**。
- **不能**（材料在**外部世界**——陌生 API 文档、别人的设计、真实服务响应；或每一步都必须**理解**而非匹配）⇒ 隔离。

**本地材料几乎总能压掉**：一个刻意做得"不可压缩"的 65 文件 / 389 KB / 97k tokens 语料（md5 全不同、关键值用十种语法表达），两路受试者**各自独立**写了个 30 行脚本，把它压成 64 行表。

> **适用边界（未做对照验证）**：判据只适用于**能用便宜手段判别**的材料。必须**逐份理解**才能得出结论的本地材料（例如"这 65 个模块里哪一处有竞态、哪条迁移不可逆"）压不掉——那时按本判据会被误判成"自己做"，把无法压缩的原文塞进自己的上下文。

## 两条不能违反的

1. **隔离与"我也做一遍"不能并存。** 两个都做 = 付两份成本、没省下任何上下文。
2. **产物是线索，不是证据**（与「自述不是证据」同源）：
   - **调研** → 结论要能追溯到出处，我抽查关键结论
   - **实验** → **实验落盘在我能重跑的位置**——这一条把"它说它试过了"变成证据
   - **外部核验** → 留下**真实响应**（不是"文档上说"）
   - **审查** → 可定位的问题（文件 + 行 + 为什么），不是"看起来还行"

## 指令必须带上评判标准

隔离型子代理**看不到我的对话**。只说"比较 A 和 B 的优劣"，会拿到一个**正确但与项目无关**的对比（通常还推荐"更灵活"的那个）。要说"**在我们这个约束下的优劣**"，并把约束列出来（例如"正确性优先、拒绝抽象层、最简即默认"）。

## 用未验证清单驱动外部核验

最终验收的"本机无法验证清单"，**每一项都先问一句**：能不能派个外部核验型子代理，把它从"未验证"变成"已验证"？能就派，不能就写明为什么不能。

## 熔断

- 拿不到凭据 / 网络 ⇒ **明确降级**为调研型并记入未验证清单。**不许假装验过了。**
- 对外部服务：**只读、单次、不批量、不写**；有副作用的操作先问用户。
- 结论与我强耦合、而我复核不了关键一环 ⇒ **不要外包理解本身**。

# 窗口可靠性工程

| 问题 | 对策 |
|---|---|
| **静默死亡**（进程消失、无退出信息） | 驱动器必须把 `EXIT=<code> DURATION=<n>s` 写进产出文件。**窗口的结局必须能从文件读出，不能靠猜。** 判据是「**有 EXIT 才说明正常收尾**」——读不到 EXIT 就是非正常结束 |
| **撞运行上限**（超时） | **续用同一会话**下发窄任务（只修失败项 + 收尾），不要重新解释上下文。实测 40 分钟超时后，窄任务 6 分钟完成 |
| 同一目录 / 包内的两个窗口 | **必须串行**——项目级检查命令（格式化 / 测试）往往是整包作用域，一个窗口的中间态会让另一个的检查假失败 |
| 跨包且文件集不相交 | 可并行；但要显式给指令"先写完 A 再改 B，别长时间破坏可编译性" |
| 并行窗口共享可变资源 | **不得共享**（同文件、同 schema、同 manifest、**以及 `.git`**）。有则串行，或指定唯一 owner |
| **同一仓库的并发提交** | `.git/index` 是**共享可变资源**：两个窗口同时 `git add`/`commit` 会撞 `index.lock`，更糟的是 A 的提交会**扫进 B 已暂存的文件**。⇒ 同一仓库同一分支的窗口**提交必须串行**。要真并行就各给一个 `git worktree` + 独立分支，由我合并 |
| 工人越界改动 | 默认禁止；但它若**判断正确**（例如把重复的白名单提为共用），**接受并记入台账** |

## 让工人产出可信的信号

值得在指令里明确鼓励这四类行为：

| 行为 | 为什么值钱 |
|---|---|
| **拒绝猜** | 规格有矛盾时**原样上报**，而不是选一边做下去 |
| **证伪自己的测试** | 例如：删掉被测的那行配置，看测试是否仍然通过——如果通过，说明测试证明的不是你以为的东西 |
| **拒绝把兜底条款执行成错的** | 指令的兜底分支若会破坏语义，**拒绝执行并说明理由** |
| **主动上报缺口** | 把没做的事具体到文件与函数 |

反过来，**采信这些自述就是失职**——见 `references/verification.md`。

**切片指令里最不能省的是「本轮约束」**（只许改哪些目录、是否禁止新增依赖、有没有不得触碰的资源）——它是历史上被越界破坏得最频繁的一节。

# 独立对抗读者（可选）

派一个**没有参与规格与派活**的 agent，逐行读交付物 + 契约，只问三件事：① 哪里自相矛盾 ② 哪里与它自己声称的规则冲突 ③ 哪里会让执行者做错事。

**值得派的时候**：交付物会被别人依赖、错误代价高、或我已连续多轮只看到"绿"而没看到过"红"——最后一种最危险，通常意味着我的检查已经和我的盲区同构了。
