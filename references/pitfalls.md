# 通用陷阱库

> **这个库会随项目增长。** 更新时机见 `SKILL.md`「收尾与自我进化」；下文定义条目是否值得入库。
> 判据：**换个项目还会踩** 才入库；项目专属的坑留在该项目的交接文档里。
>
> **入库判据补充**：这里收的是**意外**（你原本没想到会这样），不是纪律的重述——纪律在 `SKILL.md` 与 `references/` 里，不在这里重复。
> **判"是不是重复"先分类，再看后果**：① **工件**（表单里的填写提示、图上的节点标签）不参与去重，除非与权威定义冲突；② **证据**的归宿是 `VALIDATION.md`，不是工作文件；③ 只有**规则**才问"这条的**后果**在别处有没有被覆盖"——覆盖了 ⇒ 复述，删；没覆盖 ⇒ 独立条目，照收。
> **「对策」栏只写"这条意外怎么绕过去"**，不写"正确的做法是什么"——后者已经有权威，写第二遍就是给自己埋漂移。
> 技术条目是历史环境中的案例，不保证适用于所有版本、平台与项目。采用前核对当前依赖、诊断或文档；未注明核实出处的工具行为，本轮未重新核实。命令示例按实际 shell 改写。

## 流程类（与语言无关）

| 陷阱 | 后果 | 对策 |
|---|---|---|
| **把自己的答案键 / 规格当真理** | 工人的证据与你的前提冲突时，你会否掉正确答案 | 先核对规格、答案键与生成器，再裁决工人证据 |
| **并行波次里，别人的半成品文件会挡住你的测试** | 一个工人写到一半的文件（语法/类型错误）让**整个测试二进制**编译失败，别的工人连自己的测试都跑不了——而那不是它写错的 | 被挡住的一方把自己的目录**复制到临时 crate** 里跑，**不要去改对方的文件**（那会把两个工人的改动搅在一起） |
| **并行波次里"本轮提交的 SHA"不能靠读 HEAD 得到** | 另一个工人刚提交，你读到的 HEAD 是它的；交接文档里记错 SHA，验收第 2 步的归因随之失效 | 提交后回读自己那条提交的 SHA，或按**自己名下的路径**过滤 `git log` |
| **改「冻结判据」前没回读原文** | 凭记忆改写口径，给用户的问题带有错误前提，用户据此作出决定 | 改目标值或口径前逐字回读原文；发现错误时另记修订并作废错误决定，不偷改原记录 |
| **实现缺口因「写进契约」被标为已消除** | 行为要求已补进契约，但实现尚未落地，缺口在账上静默通过 | 实现缺口以实现与验收证据关闭，文档缺口以对应文档证据关闭；待实现的阻断项指向承载切片与下发指令，不以补契约替代实现 |
| **一条被证伪的说法散在多处** | 只改发现它的那一处，其它有效指令仍会引用错误前提 | 用关键短语搜索全部引用，更新有效规则；历史证据追加失效说明，不改写当时的观察 |
| **验收期望没写「允许的失败形态」** | 端到端脚本里有两条在本阶段**不可能通过**（一条依赖尚未实现的切片、一条依赖已被砍掉的功能）——不预先写清期望，真缺陷与阶段限制就分不开，还可能有人去改前端脚本「让它绿」 | 写期望时**同时写失败形态**（如「必须红在『端点缺失』」）；不符形态 = 真缺陷 |
| **昂贵命令在同一条命令里跑多遍** | 为过滤、计数、求和重复全量检查，并发争用资源还可能制造假失败 | 跑一次，保存原始输出再分析；派新门禁前确认争用同一资源的前次检查已结束 |
| **`2>&1 > file` 的重定向顺序** | 写反了 ⇒ stderr 留在终端、stdout 进文件；分析时看到「文件里什么都没有」，误判成命令失败 | 记成 `> file 2>&1`（先定 stdout，再让 stderr 跟随） |
| **提交信息描述了脚本没做成的事** | 编辑失败后后续提交照样执行，提交说明与实际改动不符 | 后续步骤以编辑成功为条件；支持的 shell 可用 `&&`，其它环境显式检查退出状态；提交前复核 diff |
| **交付物清单与「只改」范围互相不可满足** | 派活后工人才会发现：某一项交付物（例：把客户端日志写进文件）**必须改一个被禁止触碰的 crate**；它要么越界、要么交不出来，两种都糟 | 派活前做一次**一致性终检**：把每条交付物逐条问「**它的代码实际落在哪些 crate/文件里**，这些都在允许清单里吗」——**要枚举全部，不是找到第一个就算**（实测：同一片先补了 crate A，随后发现 crate B 也缺）；同理检查「必读清单点到的文件是否都存在」（可脚本化） |
| **用 `grep`/过滤管道处理测试输出**（`cargo test 2>&1 | grep -E '^test result'`） | **失败用例名被过滤掉** ⇒ 只剩"1 failed"却不知道是哪个；重跑往往不复现 ⇒ 那次失败**永远无法归因** | 原始输出**先落盘**（`> out.txt`）再在文件上过滤——**别让管道决定你看到什么** |
| **同一逻辑在新实现里出现第二份**（旧实现两处各一份，新实现照抄成两份） | 两条路径会**各自漂移**：一处改了另一处没改 ⇒ 用户看到不一致的产物 | 收口成一份（让后来者调用先落地的那份），**或**当场登记缺口并指派工人；"两处都写了指向彼此的注释"不是收口 |
| **抓日志/抓全局状态的测试与"命中同一 callsite"的其它测试并行**（例：`tracing` 的**进程级**兴趣缓存） | 无订阅者的线程把 callsite 缓存成 disabled ⇒ 抓取端偶发拿到**空结果**，断言以"提示文案缺失"的形态随机变红（改了 `rebuild_interest_cache()` 也不够——重建是全局的，别的线程会再次把它禁用） | 互斥范围要覆盖**所有命中同一 callsite 的测试**（含不抓日志的那些），不只是"抓日志的测试之间互斥"；否则锁白加。实测：只锁抓取端仍 1/1 复现，锁住兄弟用例后 30/30 绿 |

## 委托类

| 陷阱 | 后果 | 对策 |
|---|---|---|
| **重写时把旧实现当行为标准** | 产出继承未裁决的妥协，事后分不清行为来源 | 先裁决保留 / 修正 / 废弃的行为，按工人合同 §1 设置材料范围 |

## 文件与数据正确性（跨语言，**踩了通常丢数据**）

| 陷阱 | 后果 | 对策 |
|---|---|---|
| 只 rename 不 fsync | 断电后留下**空文件**，而它会被下次运行判为"已下载"从而**永久跳过** | rename 前 `fsync(file)`；rename 后 `fsync(dir)`（best-effort） |
| "存在即跳过" | 无法区分"同一对象已下载"与"不同对象恰好同名" | 跳过判据要按对象身份；必要时显式建模"清单是否完整" |
| 用内容哈希判断"是否已下载" | 没有远端摘要时，先下载才能获得摘要，无法据此省掉传输 | 按对象身份、已有可信摘要或成功记录判断；「存在且非空」只能作初筛，不能证明下载完整 |
| 并发下靠"第一个空闲槽位"分配名字 | 集合确定但**映射不确定** | 按确定序号分配；或在并发前一次性预分配 |
| 依赖哈希容器迭代序生成文件名 | 输出不确定 | 用有序容器 |
| 分页抓取部分成功后推进"已处理水位" | 中间那段**永久**不再被抓（不可恢复） | 只在**完整**抓取后推进；不完整就下次重抓 |
| 取消 / 中断路径把未完成的项当成功 | 静默丢数据 | 留下未完成状态，恢复与重试按契约执行；用户取消不自动触发继续执行 |
| 错误分类只有"可重试 / 不可重试" | "看不懂响应"被误记成"资源不存在"（永久失败），或无限重试 | 加第三类"致命"：中止并报错，保持失败记录干净 |
| 生产与消费写成两个顺序阶段 | 通道满时**死锁** | 两者并发（join），不要顺序 await |
| **同文件判定用字符串规范化**（`abspath` + `normcase` 比较） | 硬链接 / 符号链接 / 8.3 短名等**别名**绕过检查 ⇒ 例如"输出到输入自身"的保护失效，**输入被截断覆写** | 两侧都存在时优先用**文件身份**（inode + device，或等价的 `samefile`）；字符串比较只作回退 |
| **先打开输出再读输入** | 中途失败（解码 / 解析错误）时留下**半截输出**，而原内容已被截断覆盖 | 写同目录临时文件，成功后原子替换；失败时目标文件保持不变 |

## 按技术栈（**只在用该栈时读**，不是通用知识）

### Rust / Cargo

| 陷阱 | 后果 | 对策 |
|---|---|---|
| `clippy` 的 deny 列表含 `panic` | `todo!()` / `unimplemented!()` 直接挂门禁 | 占位用空结构体 + 注释 |
| `enum Foo {}` 空枚举 | 触发 `clippy::empty_enum`，`-D warnings` 下硬失败 | 占位用空结构体 |
| 工作区里 `dep = { workspace = true }` | 内部包若没在 `[workspace.dependencies]` 加 `path` 条目会直接报错 | 新增包要同时改两处 |
| `cargo fmt` 会整体翻换行符 | CRLF 文件被改成 LF，产生巨大伪 diff | 提交前检查；必要时 `.gitattributes` 固定 |
| **并行波次里运行会写入共享源码的格式化命令** | 格式化他人正在写的文件，改动无法归因 | 限定格式化范围并核对 diff；命令会遍历其它模块时在独立工作区运行，不能只凭传入一个文件名认为范围已隔离 |
| 同名依赖不同版本并存 | 混用两套 API | 以自己 manifest 声明的版本为准 |
| 声明了依赖但没用 | `unused_crate_dependencies` 默认 allow，不会被门禁抓到 | 依赖按需加，不预铺 |
| edition 2024 的 `std::env::set_var` 是 `unsafe` | `forbid(unsafe_code)` 下无法调用，测试也改不了环境变量 | 环境读取做成"注入查找函数"；需要设置时改用库的显式 API |
| **异步闭包重试抽象遇到生命周期与 `Send` 冲突** | 特定签名的 future 无法满足既有约束，多处调用编译失败 | 核对具体类型与诊断；该案例用枚举及显式参数绕开冲突，不将其推广为禁用闭包或泛型 |

### HTTP 客户端（reqwest 系）

| 陷阱 | 后果 | 对策 |
|---|---|---|
| 代理只写在配置里，没注入客户端 | **配置项是空操作**，用户完全连不上且无提示 | 显式 `Proxy::all(url)` 注入每个客户端 |
| 以为客户端库会校验代理 scheme | `Proxy::all("ftp://…")` 返回 `Ok`，非法 scheme 静默通过 | 自己维护 scheme 白名单 |
| `Error` 的 `Display` 会拼上原始 URL | URL 里的 query 凭据被写进日志 | 错误消息不打印 source；URL 先脱敏 |
| `.body(String)` 不自动加 content-type | 上游按表单解析 | 显式设置 header |
| 未开启系统代理特性 | 以为读了系统代理，其实没有 | 明确依赖的代理来源（显式注入 / 环境变量 / 系统），并写进文档 |
| **重试被加在 transport 注入缝之内** | 原案例中客户端与外层重试叠加，请求计数可能变成两层之积（客户端 6 × 外层 3），失败还被内层提前吸掉 | 验外层轮数时采用外层可重试、内层不重试的错误形态，并给 fixture 加针对该场景的变体；具体错误与主机规则按当前实现核对 |

### Windows 平台

| 陷阱 | 后果 | 对策 |
|---|---|---|
| 跟随链接取得元数据后判断链接类型 | 实际判断了目标类型，可能把链接当普通文件或目录 | 对链接本身取 [`symlink_metadata`](https://doc.rust-lang.org/std/fs/fn.symlink_metadata.html)；[`Path::is_symlink`](https://doc.rust-lang.org/std/path/struct.Path.html#method.is_symlink) 本身不跟随链接，不能笼统称该 API 报假 |
| 删除目录符号链接用删文件 API | `ACCESS_DENIED` | 先试删文件，再试删目录 |
| 对打开的句柄 rename 不可靠 | 写入丢失 | rename 前显式 drop 句柄 |
| `std::fs` 走 verbatim 路径，不做 Win32 归一化 | 带尾点 / 尾空格的旧名解析到不同路径 | 自己按平台归一化 |
| 管道 stdin 上的交互式提示死等 | 脚本 / CI 卡住 | 非终端时直接读，不走交互 API |
| 批处理块内展开变量 | 括号块内取到陈旧值 | 用顺序语句 + 标签跳转 |
| 路径前缀匹配用字符串 | `/data` 会放行 `/database` | 按路径分量比较；大小写按平台 |
| **两个 cargo 并发写同一 `target/`** | 链接期报 `LNK1104: cannot open file`（目标 exe 被另一进程占用）——**看起来像代码/环境坏了，其实是并发** | 跑门禁前确认没有别的 cargo 在跑；被挡住时**取消重复作业**再复跑，别把 `LNK1104` 当缺陷查 |
| **把 POSIX 形态的路径喂给 Windows 子进程**（`/c/Users/x/Temp/app` 当 `HOME`/根目录） | 子进程把它解释成**当前盘根**下的 `C:\c\Users\…` ⇒ 文件写到别处，而命令仍 `rc=0`、stdout 一切正常 ✗**静默走偏** | 给 Windows 子进程的路径一律用 Windows 形态（`%TEMP%`/`C:\…`）；跨平台脚本用 `tempfile.gettempdir()` / `os.environ["TEMP"]`，**别硬编码 `/tmp` 风格**；收尾时清理自己造的错位目录，**别动别进程的** |
| `cargo test` 默认 **fail-fast** | 第一个失败的 target 之后其余不再跑 ⇒ 你看到的「用例总数」**不完整**，容易误判影响面 | 要全量图景就加 `--no-fail-fast`；否则把它当「有没有红」的信号 |
| **把 `127.0.0.1:1` 当作"封网"端点**（隔离测试/基准里的"连不通"） | 在本机是**慢失败**（连接要十几秒才报错）⇒ 若被测路径会重试（客户端级 6 次尝试），整组测试从秒级变成**分钟级**，看起来像卡死；基准里更会把比值污染成十几秒 | 用**本机 accept-and-close 监听**当"不可达"端点（接受后立即关闭 = 传输错误，仍是快速失败）。判据不变，耗时回到秒级（实测 161.8s → 25.9s） |
